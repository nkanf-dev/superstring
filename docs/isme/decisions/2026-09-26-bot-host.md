# Shared Bot host decisions (PR3)

Basis: accepted refactor architecture, no reduction in existing capabilities, parent architecture review.

- Current: private and group conversation pipelines route separate fixed stages. Change: both use OneBotHost → ConversationHost → AgentRuntime; topology affects authorized recipients and phase context, not the model loop. Existing direct, follow-up, activity, idle triggers and their independent switches remain.
- Current: one global legacy Bot lease. Change: claim counts live Bot wake leases inside the same SQLite immediate transaction, default concurrency 1, configurable higher; each conversation remains serial. The same lease renews and fences commit. Web and leaf jobs do not occupy these slots.
- Current: max_recompute_count is an editable 0–2 setting. Change: it limits related-input re-observation in the new run; exhaustion fails without advancing the source cursor or submitting output. Agent step limits remain independent. No hardcoded one-review flag.
- Current: scoring fetches keyword memory with a fixed 400-unit allowance and ignores the selected `off` mode; reply uses the six-mode policy. Change: main, generation and scoring share the configured memory/knowledge policy through BotContextSource, with their distinct judgement/reply windows and model routes. Effect: off means off everywhere; full_body and all other modes remain selectable. This corrects a configuration inconsistency approved by the architecture review, and does not claim byte-for-byte prompt equivalence.
- Current: old score results are not reusable across new observations. Change: score action observations carry observedSeq, and trusted instructions expose the current source sequence. Related-input re-observation clears current eligibility. A stale score cannot authorize an output even if still visible as historical data.
- Current: unrelated group speech does not block an already relevant reply. Change: one pure relevance helper is used at draft checkpoints and delivery. Direct chats observe all eligible new input; shared replies react to actual mention/reply-to-agent and the recipient. Hard attention filtering remains effective. Every new source event is scanned, including related events buried below a later unrelated event.
- Current: activity candidates survive restart in qq_dispatch_candidates. Change: transfer them transactionally into durable wakes once, preserving path and ready time, then remove only the transferred legacy generation. Source bodies stay in the original source tables and the canonical journal remains references only.
- Current: partial confirmed sends have unresolved U13 no-reply accounting. Change: confirmed partial text is visible as retained outbound evidence without inventing a new counter decision. Unknown sends are not automatically retried. Receipt/status transitions and retention remain durable.
