# Web main Agent activation

Status: accepted under the user's delegated implementation decisions; implements reviewed refactor 02/06 A10 and PR2.

- Current: DirectService prepares an owned turn, builds context, then calls the gateway stream directly. Its cancellation, partial persistence, exact v1 SSE and idempotency contracts are existing behavior.
- Change: WebChannel holds that same lease and delegates next/invoke/observe/final to ConversationHost/AgentRuntime. DirectService only maps events to the existing v1 presentation. No model decision is synthesized from arbitrary text.
- Initial evidence: the existing ContextBuilder compatibility source prepares all configured memory modes, knowledge selection, history summaries and overview once per activation. It reserves the actual next protocol input cost before compression. Subsequent next steps retain that material and append read-only action observations; authorization and source versions are checked before further use. This executes A10, including initial semantic selection, and does not make enabled memory optional at the model's discretion.
- Supplemental reads: authorized agent/session scope and remaining context budget are host-bound. Model arguments select query and optional result count. Full memory modes retain their all-or-error semantics. No implicit sliding window replaces existing segmented compression.
- Lifecycle: prepareTurn + inbound journal append are one transaction before SSE opens. The stable assistant placeholder ID is the outputId. Successful message save, outbound journal append, captured input sequence acknowledgement and run terminal are one SQLite transaction before terminal publication. Web's explicit request cannot complete without a nonempty assistant message; none/empty returns the existing empty-response failure. Bot silence remains separate channel semantics. Failure/cancellation uses the analogous commitFailure transaction for retained partial text, journal projection and terminal; a failed terminal transaction rolls all three back and leaves truthful interrupted work for recovery.
- Cancellation: request abort and lease heartbeat reach the same runtime signal. The event bridge waits until each yielded event is consumed; early generator return aborts upstream and persists exactly the delivered partial text. A lost/cancelled lease never writes over the winning owner's result.
- Retries: a failed turn keeps its existing message ID but starts a new run/sequence. Completed turns replay existing durable text without inference or a fabricated historical run. v2 exposes full ordered runtime events; v1 retains only its strict fields and one optional context frame, accounting for the final generation context.
- Budget: generation keeps the existing model/temperature/output reserve and gateway timeout. The new iterative step budget is an injected WebChannel option (default 16); no new total wall-clock deadline is imposed on existing preparation/model work.
- Verification: retain existing SSE and ContextBuilder assertions, add actual invoke-observe-next, stable IDs, durable event sequence, replay, failed retry, and atomic rollback tests. Scripted gateways now answer the explicit next protocol rather than requiring a permissive production fallback.
