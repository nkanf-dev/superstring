# 独立评审与修订记录

> 两位子代理分别从架构/状态机和前端 UI/UX 角度独立审查当前源码与方案。以下是**设计文档评审**，不是代码实现或真实浏览器/OneBot 验收。基线 `d3167e4`，2026-09-25。

## 1. 架构审查发现及处理

| 优先级 | 独立发现 | 已写入的处理位置 |

| P0 | Web SSE 和 OneBot 意图持久化时刻不同，不能先存同一种意图再流。 | [投递时序](./05-投递与恢复状态机.md)：Web 先 StreamSession 后 delta/成功提交；OneBot 正文齐备后先 CommittedOutputIntent 再网络发送。 |

## 2. 前端 UI/UX 审查发现及处理

| 发现 | 已写入的处理位置 |

| 当前前端不止聊天：Agent/模型、记忆纠正、知识授权、QQ 绑定/方案/素材/存储都已有可编辑 UI。 | [完整功能映射](./09-前端体验与架构.md#2-现有功能必须完整迁移)与每个 PR 的前端任务。 |
| 单个 `sending` 和一份 `messages/contextUsage` 无法表达多会话、多步运行。 | [前端数据合同](./09-前端体验与架构.md#4-数据合同与状态管理)：按 conversationId/runId 的 Zustand slice 与单一事件 reducer。 |
| 现 SSE EOF 无 terminal 可被误当成功；事件缺公共归属与序号。 | [RunEvent envelope](./02-Agent运行与上下文协议.md#2-最小契约与所有权)与[断流对账](./09-前端体验与架构.md#4-数据合同与状态管理)。 |
| ContextHandle 精确 prompt 不应塞进聊天或默认流；权限变化后需重发新请求。 | [RunInspector 与用量](./09-前端体验与架构.md#3-信息架构与关键界面)和[PR 验收](./09-前端体验与架构.md#5-可访问性响应式与三个-pr)。 |

| 状态播报、键盘 dialog、窄屏/200% 缩放需一并验收。 | [可访问性与响应式](./09-前端体验与架构.md#5-可访问性响应式与三个-pr)。 |

## 3. 评审结论与实施中必须取证的边界

前端子代理完成两轮审查，三个合同级 blocker 修订后认为**前端文档可作为实施基线**；它指出的 `started` 事件缺口也已补在[RunEvent](./02-Agent运行与上下文协议.md#2-最小契约与所有权)。架构子代理对完成版复审后认为**无剩余 blocker，可作为代码实现基线**；它最后指出的媒体不可重取问题已改为 `partial/media_unavailable`，并把 0039/0040 的引用顺序及 Web turn ↔ run/output 关联写入[数据迁移](./08-迁移与验收.md#1-迁移原则与表结构)。

代码实现前仍需以真实本地模型验证结构化决策可靠性、额外决策调用的首字延迟，以真实 OneBot/NapCat 验证回执/贴图/多目标，以浏览器及桌面窗口验证视觉与可访问性，以旧库副本演练升级/恢复。这些是实施证据，不再作为架构选择悬置。[验收矩阵](./08-迁移与验收.md)
